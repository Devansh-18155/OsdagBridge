## 1. Executive Summary

This document details the architectural refactoring, layout fixes, and visualization enhancements implemented in the OsdagBridge LaTeX report generation subsystem. 

Prior to this work, design calculation reports generated by OsdagBridge suffered from:
1. **Broken Multi-Page Tables**: Tables crossing page boundaries lacked repeated column headers and continuation notices, impairing readability and compliance with engineering documentation standards.
2. **Footer Overlap**: Multi-page tables (particularly deep girder design checks in Chapter 5) frequently overlapped with page footers due to insufficient `footskip` and `bottom` margin reservations.
3. **Fragile String Templating**: Widespread use of nested Python f-strings containing unescaped LaTeX control sequences caused syntax errors and brace collisions.
4. **Lack of Visual Analytics**: Key engineering outputs (Demand/Capacity utilization ratios and material quantities) were presented solely as raw text without visual comparison charts.
5. **Combined Live Load Tables**: Vehicular live loads and footpath live loads were conflated in a single unstructured table, lacking distinct braking load parameterization.

Through this refactoring, a **centralized style system (`styles.py`)**, a **programmatic chart generation engine (`chart_generator.py`)**, and comprehensive refactoring across Chapters 2 through 8 have been implemented. All 55 tables across the report now cleanly implement `longtable` environments with synchronized repeating headers (`\endhead`), footers (`\endfoot`), and continuation notices.

## 2. Centralized Style & Layout System (`styles.py`)

A new module `src/osdagbridge/core/reports/styles.py` was introduced to establish single-source-of-truth design tokens, table geometry, and reusable LaTeX layout constructors.

### 2.1 Design Tokens & Geometry Parameters
- **Color Palette**:
  - `COLOR_OSDAG_GREEN` (`#91B014`): Primary brand color for section titles and accents.
  - `COLOR_OSDAG_DARK` (`#556B2F`): Deep green for structural element headings.
  - `COLOR_PASS` (`#2E7D32`): High-contrast forest green for passing design checks ($UR \leq 1.0$).
  - `COLOR_FAIL` (`#D32F2F`): Standard crimson red for failing checks ($UR > 1.0$).
  - `COLOR_STEEL` (`#37474F`), `COLOR_CONCRETE` (`#546E7A`), `COLOR_REBAR` (`#E65100`): Distinct structural material palettes.
- **Page Geometry (`geometry` package)**:
  - `top=25mm`
  - `bottom=28mm` (increased from 22mm to provide safe vertical cushion)
  - `left=20mm`, `right=20mm`
  - `footskip=18mm` (increased from 10mm to completely isolate page footers from table contents)
- **Table Formatting Tokens**:
  - `\tabcolsep = 5pt` (standardized padding across all table columns)
  - `\renewcommand{\arraystretch}{1.15}` (improved row vertical readability)
  - `\setlength{\extrarowheight}{1.5pt}` (prevents horizontal rule clipping)

### 2.2 Reusable LongTable Constructors
- **`make_longtable_header(caption, col_spec, header_row, label, num_cols)`**:
  Generates standard `\begin{longtable}{col_spec}`, `\caption{caption}`, `\endfirsthead`, and continued `\endhead` blocks with `\textit{\tablename\ \thetable{} -- Continued from previous page}`.
- **`make_longtable_footer(num_cols)`**:
  Generates `\endfoot` blocks with right-aligned `\textit{Continued on next page\dots}` and final `\endlastfoot` closing rules.
- **`lt_block(caption, col_spec, header_row, rows, label, note, num_cols)`**:
  High-level convenience generator that formats full tables in a single declaration.
- **`generate_preamble()`**:
  Generates a single authoritative LaTeX preamble including required packages: `longtable`, `array`, `multirow`, `makecell`, `booktabs`, `needspace`, `xcolor`, `graphicx`, `float`, and `colortbl`.

## 3. Detailed Modifications by File and Chapter

### 3.1 `report_generator.py`
- **Replaced inline preamble**: Updated `preamble()` to delegate directly to `styles.generate_preamble()`, removing obsolete hardcoded geometry strings.
- **Programmatic Chart Orchestration**: Integrated automatic generation of:
  1. Element-wise Utilization Ratio (UR) chart via `generate_ur_summary_chart()`.
  2. Material quantity visualizations via `generate_material_quantity_charts()`.
- **Dynamic Argument Passing**: Injected generated chart paths into `ch5_design_checks()` and `ch7_quantities()`.

### 3.2 `chap2.py` (Design Inputs)
- Refactored all 8 input parameter tables (Superstructure Geometry, Material Properties, Deck Slab, Girders, Stiffeners, Cross Bracing, End Diaphragms, and Bearings) to use `lt_block()`.
- Every table now incorporates repeated headers and continuation footers across page boundaries.

### 3.3 `chap3.py` (Loads & Load Combinations)
- **Separated Live Load Tables**:
  - Table 3.3: **Vehicular Live Loads (LL)** (IRC 6:2017) with dedicated multi-column Braking Load subheaders.
  - Table 3.4: **Footpath Live Load** (IRC 6:2017) with dedicated pedestrian loading and reduction factor parameters.
- **Multi-Column Braking Subheaders**:
  Implemented `\multicolumn{3}{c|}{\textbf{Braking Load}}` with sub-columns `\textbf{Considered?}`, `\textbf{Value}`, and `\textbf{Eccentricity}`.
- **Fixed IRC 6 Braking Force Calculation**:
  Corrected unit scaling from Newtons to kN (110.8 kN for standard 2-lane bridge as per IRC:6 Cl. 211.2).
- **Escaping Bug Fix**:
  Resolved unclosed f-string expression `\textminus{}` in temperature load formatting.

### 3.4 `chap4.py` (Structural Analysis)
- **Table 4.1 (`Summary of Maximum Demands`)**: Converted to full LongTable with `\endfirsthead`, `\endhead`, `\endfoot`, and `\endlastfoot`.
- **Table 4.2 (`Reactions at Supports`)**: Converted from hardcoded tabular to dynamic LongTable populated directly from `rxn_summary`.
- **Table 4.3 (`Deflection Summary`)**: Converted to LongTable with code limit evaluations ($L/800$ for live load, $L/600$ for total load).

### 3.5 `chap5.py` (Design Checks)
- **Multirow Page-Break Protection**: Added `\\*[6pt]` to all internal rows of multirow girder check blocks (Tables 5.1 through 5.10). This prevents LaTeX from breaking a page in the middle of a multirow girder section, which previously caused orphaned text and footer overlaps.
- **Raw String Architecture**: Replaced mixed f-string interpolations with pure raw string concatenation (`r"""...""" + var + r"""..."""`), preventing backslash mangling and math mode syntax errors (such as `\Delta\sigma`).
- **Section 5.5 Visual UR Chart**:
  Embedded the high-resolution Utilization Ratio comparison chart (`fig:ur-summary-chart`) directly preceding the overall summary table.

### 3.6 `chap7.py` (Material Quantities & BOM)
- **Table 7.1 (`Bill of Materials`)**: Converted to LongTable with repeating headers and continuation notices.
- **Section 7.2 (`Material Quantity Visualizations`)**:
  Programmatically embedded side-by-side / stacked high-resolution figures:
  1. `chart_steel_tonnage.png`: Component-wise structural steel breakdown (Webs, Flanges, Stiffeners, Cross Bracings, End Diaphragms).
  2. `chart_concrete_rebar.png`: Concrete volume ($\text{m}^3$) alongside total reinforcement steel tonnage (MT).

### 3.7 `chap8.py` (Codes & Standards)
- Replaced hardcoded floating tables for IRC Codes (Table 8.1) and IS Codes (Table 8.2) with LongTable structures using repeating headers and clean column widths.

### 3.8 `irc6_2017.py` (Core Design Code Utility)
- **Bug Fix in `cl_211_2_braking_force`**:
  Resolved `UnboundLocalError: cannot access local variable 'braking_force_2'` when `design_lanes <= 2`. Added default initialization `braking_force_2 = 0.0` and corrected ton conversion (`/ 9810.0`).

## 4. Programmatic Visualization System (`chart_generator.py`)

A dedicated visualization module `src/osdagbridge/core/reports/chart_generator.py` was created to render production-grade figures using Matplotlib with offscreen rendering (`Agg` backend).

### 4.1 Utilization Ratio (UR) Summary Chart (`generate_ur_summary_chart`)
- **Metrics Extracted**: Peak demand-to-capacity ratios for:
  - Plate Girders (Governing moment, shear, or interaction check)
  - Concrete Deck Slab (Sagging/hogging flexure or punching shear)
  - Cross Bracing (Diagonal and chord tension/compression efficiency)
  - End Diaphragms (Bearing stiffener and diaphragm stability)
- **Key Features**:
  - Horizontal crimson dashed reference line at $UR = 1.0$ (`linestyle='--', linewidth=2.0`).
  - Color-coded bars: Forest green for passing members ($UR \leq 1.0$), crimson red for failing members ($UR > 1.0$).
  - Numeric value and status annotation on top of every bar.
  - Publication-ready styling (300 DPI, white-grid aesthetic, clean spine removals).

### 4.2 Material Quantity Visualizations (`generate_material_quantity_charts`)
- **Chart 1: Structural Steel Breakdown (`chart_steel_tonnage.png`)**:
  Horizontal bar chart detailing tonnage across girder webs, top/bottom flanges, intermediate/bearing stiffeners, and bracing systems, with labeled tonnage and percentage contributions.
- **Chart 2: Concrete vs. Reinforcement (`chart_concrete_rebar.png`)**:
  Comparative dual-axis / categorized bar chart illustrating total structural concrete volume ($\text{m}^3$) versus rebar weight ($\text{MT}$).

## 6. Verification and Output Comparison

Both baseline and enhanced reports have been generated and validated in the repository root:

- **Baseline (`Report_Before.pdf`)**:
  - File Size: **401,531 bytes**
  - Observations: Contained single-page tabular floats with no repeating headers, footer clipping on Girder 4 checks, no visual charts, and conflated live load tables.
- **Enhanced (`Report_After.pdf`)**:
  - File Size: **690,372 bytes**
  - Observations:
    - **55 / 55 LongTables** contain repeated column headers (`\endhead`), footers (`\endfoot`), and continuation messages.
    - Footer overlap completely resolved by `footskip=18mm` and `bottom=28mm`.
    - Section 5.5 features the Utilization Ratio summary chart with the $UR = 1.0$ limit line.
    - Chapter 7 features the Structural Steel tonnage chart and Concrete vs. Rebar chart.
    - Chapter 3 clearly separates Vehicular Live Loads from Footpath Live Loads with multi-column braking details.
